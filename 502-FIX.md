# 🔧 502 Bad Gateway Fix

## Root Cause

The 502 error occurs because:
1. EC2 instance starts immediately
2. User data script tries to download from S3
3. S3 deployment might not be complete yet
4. Streamlit app fails to start or takes too long
5. ALB health checks fail → CloudFront gets 502

## Solution Applied

### Updated `user_data_script.sh`

The script now:
1. ✅ Checks if S3 bucket has files before downloading
2. ✅ Creates a placeholder Streamlit app if S3 is empty
3. ✅ Adds proper logging to `/var/log/user-data.log`
4. ✅ Waits for Streamlit to start before completing
5. ✅ Verifies service is running

## Common Issues

### Issue: S3 Bucket Empty
**Symptom:** Placeholder app shows instead of real app
**Fix:** The CDK stack deploys files to S3. If you see placeholder, wait a few minutes and restart EC2.

### Issue: Python Dependencies Fail
**Symptom:** Streamlit service fails to start
**Fix:** Check `/var/log/user-data.log` for pip errors

### Issue: Port 8501 Not Listening
**Symptom:** ALB health checks fail
**Fix:** 
```bash
sudo systemctl restart streamlit
sudo journalctl -u streamlit -f
```

### Issue: Security Group Blocking
**Symptom:** ALB can't reach EC2
**Fix:** Verify security group allows port 8501 from ALB

## Quick Fix Script

```bash
#!/bin/bash
# Run this on the EC2 instance if Streamlit isn't starting

cd /home/ec2-user/wafr-app

# Check if files exist
if [ ! -f "ui_code/WAFR_Accelerator.py" ]; then
    echo "App files missing! Downloading from S3..."
    aws s3 sync s3://wafr-accelerator-app-*/app/ . --region us-east-1
fi

# Install dependencies
python3.12 -m pip install -r requirements.txt

# Restart service
sudo systemctl restart streamlit

# Check status
sudo systemctl status streamlit
```
